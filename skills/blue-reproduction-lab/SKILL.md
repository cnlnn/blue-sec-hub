# Security Reproduction Lab

## Workflow

1. 保存来源、版本、发布日期、原始 PoC 和预期现象；将作者结论视为待验证材料。
2. 固定操作系统、应用、依赖、配置、镜像摘要和源码 commit。
3. 先复现正常行为，再执行最小触发；记录请求、输出、崩溃、日志、堆栈和网络证据。
4. 复现失败时系统比较版本、补丁、依赖、编译参数、默认配置、架构和环境假设。
5. 使用 `blue-security-knowledge` 查找漏洞机理和变体，使用 `blue-evidence-validation` 判断是否真正达到原文声称的影响。
   PayloadsAllTheThings 中生产环境默认阻止的命令、反向连接、持久化和高负载样例，只有
   在目标绑定、隔离且可重建的实验环境中才能取用；实验结果不得自动改变线上 Runner 的
   payload 策略。
6. 产出一键重建步骤、验证脚本、检测特征、受影响条件、修复方法和清理步骤。

明确区分“PoC 运行成功”“漏洞触发成功”和“影响已得到验证”。
