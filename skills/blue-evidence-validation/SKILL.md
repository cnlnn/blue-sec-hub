# Evidence Validation

## Validation Gates

1. `observed`: 原始证据实际显示了什么，不加入解释。
2. `reachable`: 当前入口、代码路径或状态是否可达。
3. `controlled`: 单一变量变化是否导致预期结果。
4. `owned`: 身份、租户、对象和资源所有权是否得到验证。
5. `repeatable`: 是否在记录的条件下稳定复现。
6. `impact`: 是否发生了具体的机密性、完整性、可用性或权限影响。
7. `alternative`: 缓存、公开数据、代理、正常功能、历史状态或环境差异能否解释现象。
8. `provenance`: 攻击链所需的 opaque 标识、状态和能力是否能由当前攻击者路径获得。
9. `publication-intent`: 数据是否由公开页面、文档、字段语义和业务受众明确设计为公开。

## Rules

- 静态证据可以建立假设，不能单独证明后端授权失效或运行时影响。
- HTTP 200 必须结合响应语义、身份、对象和对照请求解释。
- 扫描器结论必须回到原始请求、响应或代码路径。
- 历史报告与本次新证据必须分栏。
- 历史日志或报告中的对象标识只能作为测试种子；无法从本次攻击者可达入口重新获得时，
  不得把它写成完整黑盒攻击链。
- 公开目录、公开业务数据和正常文件上传只有在超出预期受众，或产生解析、存储、执行、
  授权影响时才构成漏洞。
- 无法复现不等于已修复；已修复需要修复机制和当前行为共同支持。
- 复合漏洞必须先画出前提链。单一策略 Header、可疑参数、上传成功、sink、处理器可达或
  回显只完成对应节点；具体入口、攻击者可获得的输入/对象、身份或浏览器上下文、消费
  动作和实际影响未证明前保持 candidate，并继续寻找缺失节点。
- 通用前提使用 `pending`、`searching`、`satisfied`、`exhausted-with-evidence` 或
  `blocked-external`。终态必须有本轮证据；证据化穷尽只能支持排除候选，不能支持确认，
  也不能让仍适用的测试通过覆盖门槛。对象授权必须先证明当前可达生产者、自有对象基线
  和真实消费者，随机不存在 ID、历史 ID 或未知所有权 ID 不能代替。
- CORS 必须区分“响应声明跨域策略”与“浏览器能带受害者凭据读取受保护的具体接口”。
  `Access-Control-Allow-Origin`、HTTP 200 或响应含敏感字段名均不能单独确认影响。

输出结论、证据编号、反证、剩余不确定性和最小下一步。
